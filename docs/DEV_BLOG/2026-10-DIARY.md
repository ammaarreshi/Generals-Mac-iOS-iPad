# Development Diary - October 2026

## 2026-10-23: Modern-warfare mod proposal ("Zero Hour: Kill Chain")

Design-only session. Nothing in the game, the INIs, the install or
the engine was changed. The output is a proposal for an opt-in mod
that moves USA / China / GLA into 2025-26 warfare: drones, EW,
counter-UAS, top-attack threats to armor, finite deep strike, and
modern conventional superweapons.

Docs added:
- `docs/WORKDIR/reports/modern-warfare-mod/`
  - `research-usa.md`, `research-china.md`,
    `research-irregular-and-trends.md` (open-source research; GLA stays
    fictional, nothing operational).
  - `fact-check.md`: 27 load-bearing claims checked. The design relies
    on none marked Contradicted or Unconfirmed.
  - `engine-mod-surface.md`: what INI can express in GeneralsXZH, with
    mod loading, module catalog, fixed enums, hard limits and CRC rules.
- `docs/WORKDIR/planning/modern-warfare-mod/`
  - `PROPOSAL.md` (rev 4, all design questions answered).
  - `PROPOSAL-REVIEW.md`: independent code-grounded review of rev 1
    (3 blockers, all fixed in rev 2).

Engine facts found along the way, all with file:line in the docs:
- `EMPUpdate`'s victim KindOf filter is commented out, so EMP can't be
  made drone-only from data.
- `SubdualDamageHelper::notifySubdualDamage` resets the heal countdown
  on every hit, so stacked subdual pulses never heal. Jamming is
  designed around `SUBDUAL_MISSILE`, which only projectile armors take.
- `PointDefenseLaserUpdate` creates a fresh weapon per shot, so
  `ClipSize`/`ClipReloadTime` are ignored.
- `SpawnBehavior` needs an exit interface. The Angry Mob is the only
  retail mobile spawner.
- **Real bug:** `ArmorTemplate::parseArmorCoefficients` (and
  `DamageFX.cpp`) don't check `getSingleBitFromName()` for -1, so an
  unknown or misspelled damage name in `Armor.ini` writes
  `m_damageCoefficient[-1]`. Retail data never hits it, but mods can.

Decisions that affect the engine:
- A new `DAMAGE_TOP_ATTACK`, appended after `DAMAGE_STATUS`, is planned
  as Phase 0B. Ordinals don't shift. Saves store damage flags by name,
  and the CRC hashes the bitset's byte size, which stays 8 bytes for
  38-40 bits. Retail CRC, saves and replays should be byte-identical.
  The proposal has a replay-regression plan to confirm this.
- The bounds-check fix and `DAMAGE_TOP_ATTACK` are to be offered
  upstream to TheSuperHackers as two separate PRs, after they land
  here.

Not committed: the retail INIs extracted for reference stayed in the
session scratchpad (retail data doesn't belong in the repo). There is
still no BIG pack/unpack tool in the repo; that is Phase 0.

Next, if green-lit: Phase 0 tooling, the Phase 0A W3D export spike
(FPV quadcopter proof asset), then Phase 0B.
