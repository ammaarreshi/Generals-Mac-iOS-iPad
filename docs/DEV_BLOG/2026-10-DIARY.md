# Development Diary - October 2026

---

## 2026-10-13: iOS 27 / Xcode 27 / A13 bring-up fixes

First build of the iOS target on a fresh machine (Xcode 27, iPhoneOS
27.1 SDK) and a first run on an older iPad. Three separate problems,
each found from the device logs (`Documents/generals-stderr.log`).

Build:
- `meson setup` for DXVK stopped with "Missing Vulkan-Headers". The
  README only initialised `references/fbraz3-dxvk`, not its nested
  submodules (Vulkan-Headers, SPIRV-Headers, ...). README now uses
  `--init --recursive`.
- `dxvk_pipemanager.cpp` failed to compile against the Xcode 27
  libc++: `emplace(piecewise_construct, tuple<>(), ...)` makes
  `__try_key_extraction_impl` instantiate `tuple_element<0, tuple<>>`
  (hard error, not SFINAE). `createNullFsPipelineLibrary()` now passes
  its default-constructed key explicitly. Added to
  `Patches/dxvk-ios.patch`.
- Gotcha: DXVK is an ExternalProject, so editing its sources does not
  trigger a rebuild. After touching `references/fbraz3-dxvk`, run
  `ninja -C build/ios-vulkan/_deps/dxvk-build-macos` before packaging.

A13 (iPad 9th gen):
- Startup died with the classic "DirectX 8.1 or higher" fatal. Real
  cause in the MoltenVK log: `VK_ERROR_FEATURE_NOT_PRESENT ... 1st flag
  in VkPhysicalDeviceVulkan12Features` = `samplerMirrorClampToEdge`,
  which D3D9 enabled unconditionally and MoltenVK does not expose on
  A13. Now enabled only when supported; MIRRORONCE samplers fall back
  to MIRRORED_REPEAT (the game never uses MIRRORONCE anyway).

iPadOS 27 orientation:
- Main menu was cropped and offset; log showed the backbuffer flipping
  to 1620x2160 (portrait) on a landscape 2160x1620 screen, and the game
  falling back to 800x600.
- Root cause in SDL 3.4.2 `UIKit_ComputeViewFrame()`: it trusts the
  deprecated `statusBarOrientation`, which on iPadOS 27 disagrees with
  the scene, then "fixes" the landscape frame to portrait.
- New `Patches/sdl3-ios.patch` reads `windowScene.interfaceOrientation`
  (active scene during window setup). Applied to the FetchContent
  source via `cmake/apply_patch_once.cmake` (`patch -p1`, idempotent):
  plain `git apply` silently skipped it because `build/` is inside this
  repo and git resolved the paths against the repo root.
- First attempt forced landscape sizes in `W3DDisplay.cpp` /
  `SDL3Main.cpp`; dropped once the SDL cause was found.

Validation (native-resolution landscape main menu):
- iPad 9th gen (A13), iPadOS 27.0: 2160x1620
- iPhone 14 Pro, iOS 27: 2556x1179
- iPhone 17, iOS 27.0.1: 2622x1206

Not a bug: "no audio" on iPad was Silent Mode. OpenAL output is muted
by the default audio session category, as Apple expects for games.
